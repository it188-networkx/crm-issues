## 二、发现的问题（Bug）

### BUG-OPP-01【高】商机状态枚举多出「回退」状态

- **问题模块**：商机
- **问题功能**：商机状态（`opp_status`）枚举
- **实际表现**：商机列表筛选器「商机状态」下拉选项为 5 项：`活跃 / 回退 / 成交 / 失单 / 搁置`；商机详情页「商机状态」字段也出现值为「回退」的数据
- **预期表现**：商机状态应为 4 态：`活跃 / 搁置 / 成交 / 失单`。「回退」是阶段操作动作（`stage_action='rollback'`），**不改变商机状态**（SSOT `10-商机阶段状态操作卡.md` §3/§4 明确「回退必须填写明确原因；不改变商机状态——搁置是独立的状态操作」）
- **复现步骤**：
  1. 登录系统，进入「商机管理」
  2. 点击筛选器「商机状态」
  3. 观察下拉选项，存在「回退」项
- **原型对应位置**：商机列表筛选器「商机状态」
- **关联需求文档**：`field-specs/10-商机阶段状态操作卡.md` §3（stage_action 与状态映射表）、§4（回退不改变状态）；`field-specs/04-商机.md` §阶段与状态（商机状态 = 活跃/搁置/成交/失单）
- **严重程度**：高（状态枚举污染，影响筛选/统计口径）
- **截图**：`screenshots/opp-01-status-filter.png`

### BUG-OPP-05【高】CRM 保留「标记成交」按钮与手动成交表单，违反 08-27 定案

- **问题模块**：商机
- **问题功能**：跟进创建页「🔄 阶段/状态操作」卡片
- **实际表现**：新建跟进（完整表单模式）关联商机后，阶段/状态操作卡片展示 7 个按钮：`— 无阶段/状态变更 — / ⬆ 推进阶段 / ⬇ 回退阶段 / ✅ 标记成交 / ❌ 标记失单 / ⏸ 标记搁置 / ▶ 唤醒`。点击「✅ 标记成交」展开完整手动成交表单：`成交金额(万)* / 签约日期* / 归因渠道* / 关键影响因素（多选）*`（价格优势/技术方案/客情关系/品牌认知/服务响应/竞品退出/政策因素 7 项）
- **预期表现**：按 `10-商机阶段状态操作卡.md` §一/§五（2026-08-27 用户定案），CRM **不提供「标记成交」**——销售最多推进阶段至「签约中」；成交终态**只能由 BPM 合同签署完成后回调 CRM** 回写（close_amount/sign_date/attribution_channel/key_factors 全部由 BPM 回调携带，CRM 不提供收集/补录入口）。§5.2 明确「不再提供 CRM 手动成交（原 sa-win 路径已废除）」。动作枚举表（§二）只有 advance/rollback/lose/pause/wake/NULL，**无 win**
- **复现步骤**：
  1. 进入「跟进记录」→「新建跟进」→「完整表单」
  2. 关联任一活跃商机（如「请问-达美乐披萨-冠服联平台-披萨合约」）
  3. 观察「🔄 阶段/状态操作」卡片含「✅ 标记成交」按钮
  4. 点击「✅ 标记成交」，展开手动成交表单（成交金额/签约日期/归因渠道/关键影响因素）
- **原型对应位置**：跟进创建页「🔄 阶段/状态操作」卡片（`#stage-action-card`）
- **关联需求文档**：`field-specs/10-商机阶段状态操作卡.md` §一、§二（动作枚举无 win）、§五（成交由 BPM 回调回写）；`architecture/data/opportunity.md` §WinCloseRecord（CRM 不提供手动成交表单）；`crm-field-mapping-full.md` §1568（sa-win 面板已移除）
- **严重程度**：高（保留已废除的 sa-win 手动成交路径，可能导致销售绕过 BPM 直接结案，与「成交权威源=BPM」定案冲突）
- **截图**：`screenshots/opp-stage-action-card-has-win-button.png`、`screenshots/opp-manual-win-form-confirmed.png`

### 待确认项：跨阶段跳转（需求调研→签约中）未触发门控与补录

- **实际表现**：新建跟进关联商机「请问-达美乐披萨（需求调研）」→ 推进阶段选「签约中」→ 填原因提交 → 直接归档成功，阶段变为「签约中」。期间：
  - 未触发「采购模式门控」（该商机采购模式=待确认，按 §3.3 方案设计及之后应阻断）
  - 未触发「BR-18 签署主体门控」（签约中应强制企查查刷新 + proposed_signing_entity_id 显式单选）
  - 未触发「跨阶段跳转补录」（04-商机.md 规则 6：非相邻跳转需补录 4 项）
  - 推进面板提示「当前阶段没有已启用的推进规则，请在业务配置中检查门控规则」
- **判定倾向**：门控为**配置驱动**（「业务配置 → 阶段门控」Tab，仅 4 个关键流转节点配置必填校验；BR-18 依赖工商主体数据）。测试环境可能**未配置门控规则或缺少主体数据**，导致跳过门控。**需与开发/产品确认：门控规则是否已在测试环境配置；若已配置仍被跳过则为 bug**
- **截图**：`screenshots/opp-advance-to-signing-no-gate.png`
- **已验证正常**：推进/回退的「变更原因必填 + 阶段变更记录完整 + 立项风险联动重算（🟡中↔🔴高）」均正常；回退后阶段回到「需求调研」，数据基线已恢复
