## 二、发现的问题（Bug）

### BUG-AC-01【高】客户类型枚举缺「企业客户」（3 类 vs 需求 4 类）

- **问题模块**：客户
- **问题功能**：客户类型（`customer_type`）枚举
- **实际表现**：客户列表筛选器「客户类型」下拉只有 3 项：`渠道客户 / 终端客户 / 外单客户`
- **预期表现**：需求应为 4 类：`终端客户 / 渠道客户 / 外单客户 / 企业客户`（2026-08-25 对齐线上 4 类）
- **复现步骤**：
  1. 进入「客户管理」，点击筛选器「客户类型」
  2. 观察下拉只有 3 项，缺「企业客户」
- **原型对应位置**：客户列表筛选器「客户类型」、新建客户「客户类型」
- **关联需求文档**：`field-specs/03-客户基础信息.md` §企业身份（客户类型 4 类）
- **严重程度**：高（枚举缺失，影响客户分类与筛选）
- **截图**：`screenshots/ac-02-type-filter.png`

### 待确认项：客户状态「潜在客户」vs 需求「潜客」

- **实际表现**：线上客户状态为 `潜在客户 / 商机推进中 / POC中 / 签约中 / 交付中 / 续约中 / 有风险 / 已流失`（8 值）
- **需求定义**：`潜客 / 商机推进中 / PoC中 / 签约中 / 交付中 / 续约中 / 风险客户 / 流失`（8 值）
- **差异点**：「潜在客户」vs「潜客」；「POC中」vs「PoC中」（大小写）；「有风险」vs「风险客户」；「已流失」vs「流失」
- **判定**：`review/online-vs-prototype-extract-checklist-20260827.md` 条目 4-3 记载「线上为准」；`system-vs-doc-check-checklist.md` B3.2/B3.3 记载「潜在客户 vs 潜客，以系统为准」「POC中/PoC中 大小写不统一，以系统为准」。**属命名差异，以系统为准，非 bug**（但「有风险 vs 风险客户」「已流失 vs 流失」的差异建议确认是否需统一）

### 部门必填性差异（待确认，非 bug 判定）

- **实际表现**：新建/编辑联系人表单「部门」无 `*` 必填标记，不填部门可成功保存
- **需求口径冲突**：
  - SSOT `02-联系人.md` §基本身份信息：部门「是」（必填）
  - `contact-management/README.md` §业务对象定义：部门「选填」
  - `03-客户基础信息.md` §规则 9：仅「**新建客户弹窗首个联系人**」部门必填（本测试场景为已有客户详情页新增联系人，不适用）
- **判定**：属文档内部口径冲突（SSOT vs 派生 README），本场景（客户详情新增联系人）以「选填」看待，**暂不判 bug**，建议产品统一口径
